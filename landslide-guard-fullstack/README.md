# Landslide Guard — Full Stack

A React frontend, a Node.js/Express API, and a Python FastAPI ML service
working together for early landslide-risk detection and response
coordination.

## Architecture

```
┌────────────────────┐      REST/JSON      ┌──────────────────────┐      REST/JSON      ┌───────────────────────────┐
│  React frontend     │  ───────────────▶  │  Node.js + Express    │  ───────────────▶  │  Python FastAPI ml-service │
│  (landslide-guard/) │  ◀───────────────  │  API (server/)         │  ◀───────────────  │  (ml-service/)              │
└────────────────────┘                     └──────────────────────┘                     └───────────────────────────┘
                                             JWT auth, zones,                             XGBoost + Random Forest +
                                             sensors, reports,                            SHAP explainability +
                                             alerts, priorities,                          GeoPandas + Rasterio
                                             lowdb (JSON) storage                         geospatial features
```

- **`landslide-guard/`** — the React/Vite frontend (unchanged UI, now wired to live data via `src/api/client.js` and `src/api/hooks.js` instead of static mock data).
- **`server/`** — Node.js + Express backend. Handles auth (JWT), zones, sensor readings, field/citizen reports, alerts, response-priority ranking, and proxies AI prediction requests to the ML service.
- **`ml-service/`** — Python FastAPI service. Runs the XGBoost risk model (primary), a Random Forest baseline for comparison, SHAP for per-prediction explainability, and GeoPandas/Rasterio for geospatial zone feature extraction (elevation, derived slope, nearby villages).

## Quick start

You need **3 terminals** (or run them in the background) — start the ML service first, since the Node API calls it.

### 1. ML service (Python / FastAPI)

```bash
cd ml-service
pip install -r requirements.txt   # add --break-system-packages on Debian/Ubuntu system Python
python -m app.train_model         # trains XGBoost + Random Forest, ~10-20s
python -m app.generate_geo_data   # generates the synthetic DEM + villages layer
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```
Runs on **http://localhost:8000**. Docs at `http://localhost:8000/docs`.

(`main.py`'s startup hook also auto-trains the models on first run if you skip the manual step above.)

### 2. Node API (Express)

```bash
cd server
cp .env.example .env
npm install
npm run dev      # or: npm start
```
Runs on **http://localhost:4000**. Seeds itself with demo zones/sensors/reports/alerts on first run (`server/src/data/db.json`).

### 3. Frontend (React / Vite)

```bash
cd landslide-guard
npm install
npm run dev
```
Runs on **http://localhost:5173** (or whatever Vite picks). Talks to the Node API at `http://localhost:4000` by default — override with a `.env` file containing `VITE_API_URL=http://your-api-host:4000`.

If the backend isn't reachable, the frontend gracefully falls back to the original bundled mock data (see `src/api/hooks.js`) so the UI never breaks — but the AI Prediction page requires the backend to be running, since it no longer has a mock fallback.

## What's real vs. what's synthetic

- **Risk prediction models**: genuinely trained (XGBoost + Random Forest) on a synthetic-but-domain-informed dataset (`ml-service/app/train_model.py`) — there's no public real-time labelled landslide dataset bundled here. Swap in a real dataset with the same feature columns (`rainfall`, `soil_moisture`, `slope`, `terrain_encoded`, `historical_events`) and retrain.
- **SHAP explainability**: real SHAP `TreeExplainer` output against the trained XGBoost model — not mocked.
- **GIS data (DEM + villages)**: synthetic, generated by `ml-service/app/generate_geo_data.py`, covering the same North-East India bounding box as the zone mock data. Swap `ml-service/data/dem.tif` for a real SRTM/Bhoomi DEM clip and `ml-service/data/villages.geojson` for a real settlements layer — `geo.py` doesn't need to change.
- **Database**: `lowdb` (a JSON file) for the prototype, zero-config. See "Going to production" below for the PostgreSQL/PostGIS migration path.
- **Weather forecast**: real, live data from [Open-Meteo](https://open-meteo.com) (no API key needed) — current conditions + 5-day rainfall outlook for each zone's coordinates. `server/src/services/weatherClient.js`, exposed at `GET /api/weather?zoneId=zone-a`.
- **Satellite imagery**: real NASA [GIBS](https://wiki.earthdata.nasa.gov/display/GIBS)/[Worldview](https://worldview.earthdata.nasa.gov) snapshots (true-color + IMERG precipitation overlay) for each zone's bounding box, plus a deep link into the full Worldview app. `server/src/services/nasaClient.js`, exposed at `GET /api/weather/satellite?zoneId=zone-a`.
- **Sensor network (rainfall/soil moisture/temperature/slope stability)**: fully synthetic — there's no physical IoT hardware behind this prototype. `server/src/services/simulate.js` runs a random-walk simulation for every zone once a minute in the background, and `POST /api/sensors/simulate` triggers an extra tick on demand. Swap this module for a real MQTT/HTTP ingestion pipeline to go live.

## Tech stack implemented

| Layer | Technology | Where |
|---|---|---|
| Main backend API | Node.js + Express | `server/` |
| Auth | JWT + bcrypt | `server/src/middleware/auth.js`, `server/src/controllers/auth.controller.js` |
| ML service | Python + FastAPI | `ml-service/main.py` |
| Primary risk model | XGBoost | `ml-service/app/train_model.py`, `app/model.py` |
| Baseline/comparison model | Random Forest (scikit-learn) | same |
| Explainability | SHAP | `ml-service/app/model.py` |
| Preprocessing | Pandas + NumPy | `ml-service/app/train_model.py` |
| Geographic/vector data | GeoPandas | `ml-service/app/geo.py` |
| Raster/DEM data | Rasterio | `ml-service/app/geo.py` |
| API-to-API calls | Axios (Node → FastAPI) | `server/src/services/mlClient.js` |

Not implemented (flagged as low-priority / optional in the original stack discussion): OpenCV (crack-photo image analysis), LSTM (rainfall time-series forecasting), and PostGIS (a real Postgres+PostGIS server isn't provisioned for this prototype — `lowdb` stands in, see below).

## Going to production

- **Database**: replace `server/src/config/db.js` (lowdb) with a `pg` connection pool against PostgreSQL + PostGIS. The data shapes in `server/src/utils/seed.js` map directly onto a `zones` table with a `geometry(Point, 4326)` column, a `sensor_readings` table, etc.
- **Auth**: the JWT flow is already production-shaped; just move `JWT_SECRET` to a real secrets manager and add refresh tokens if needed.
- **ML service**: containerize `ml-service/` separately (it has its own `requirements.txt`) and put it behind the same network as the Node API — it's never exposed directly to the frontend.
- **CORS**: set `CORS_ORIGIN` in `server/.env` to your real frontend origin instead of `*`.
